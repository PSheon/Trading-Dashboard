# Solana 聰明錢包研究系統 Spec

Sep 29, 2026 · @Paul · v3（取代舊版「聰明錢包建檔系統 Spec」；過去的證據與決策見 [決策紀錄](決策紀錄.md)）

## 要回答的問題

> 在 D 日**當時就能知道**的錢包中，依 D 日**當時的資料**排名前 N 名，跟單它們在 D 到 D+7 日之間的買入，在延遲 L 秒、扣除跟單者自己的手續費與滑價後，每筆跟單的期望報酬是否顯著大於 0，並優於同一批候選錢包的隨機組合。

這是唯一的成功標準。任何工作都要能說明它如何幫忙回答這個問題；說不出來就不做。

答案是「是」，才進入下一階段（即時訊號、跟單）；答案是「否」，回頭重新定義候選錢包或評分，不做 UI 與部署。

## 範圍：自己做什麼、用現成的什麼

市面上已有大量錢包追蹤、PnL 與「聰明錢」排行（GMGN、Vybe、Birdeye 與眾多開源工具），但它們給的都是**現在**的狀態。拿今天的排行或標籤回頭挑錢包，就是前視偏差。本系統唯一不可替代的部分，是**沒有前視偏差、沒有存活者偏誤的歷史資料與回測**。

| 自己做（不可替代） | 用現成的 |
| --- | --- |
| point-in-time 發現漏斗與其歷史重播（Dune，查詢帶時間上界） | 錢包交易歷史的快速取得：GMGN activity（已解析、含 USD、完整歷史） |
| 錢包在每個日期的指標快照（只用當日之前的資料） | SOL/USD 每分鐘價格：Dune `prices.usd`（以合約地址過濾） |
| 跟單回測：延遲、費用、滑價的模擬與顯著性檢定 | 代幣價格序列：GMGN K 線（1 分鐘）或 Dune 成交 |
| 經過對帳驗證的原始交易管線（Helius，作為正確性基準） | 首筆入金來源、錢包標籤：GMGN（僅從今天起每日存檔，見原則 3） |

不做：下單、即時推播、UI 擴充、部署、多鏈、代幣安全過濾。現有的網頁維持唯讀檢視，不再投入。

## 原則

1. **Point-in-time**：D 日的任何數字只能來自 D 日 00:00 UTC 之前發生的事件。所有計算強制帶時間上界。
2. **錢包池也是 point-in-time**：錢包在被漏斗發現（`first_seen_at`）之前，不屬於任何回測宇宙；回測的錢包池由漏斗**在當時**的結果決定，不用今天的名單。
3. **外部的「現在值」不能回填歷史**：GMGN / Vybe 的標籤、分數、PnL 排名只描述查詢當下。只能從開始存檔的那天起往後累積，用於那天之後的回測；歷史事實（例如某筆交易的時間、首筆入金來源）則可直接使用。
4. **不刪錢包、原始資料不可變**：原始回應只追加；衍生資料都能從原始資料重建。
5. **跟單者的成本自己模擬**：領頭錢包付了多少機器人費用與跟單者無關；跟單的延遲、手續費、滑價一律是回測參數，並做敏感度分析。

## 架構

```text
Dune ──(漏斗，帶時間上界)──▶ 各週的候選錢包 ──┐
                                            ▼
GMGN activity ──(每個候選錢包的完整交易)──▶ 領頭交易（買入時間、代幣）
GMGN K 線 / Dune 成交 ──▶ 跟單者在 t+L 的成交價
                                            ▼
               評分（只用 t 之前的交易） → 排名 → 跟單模擬 → 報酬分布與檢定

Helius ──▶ 原始交易 ──▶ 正規化、FIFO ──▶ 經對帳驗證的交易與指標（正確性基準，抽樣比對 GMGN）
```

- **兩條資料線的分工**：回測用 GMGN activity，因為快（一個活躍錢包的完整歷史約 30 秒）且覆蓋完整。Helius 管線是正確性基準：它在 P0 與 50 個漏斗錢包上的對帳可信列 100% 一致，用來抽樣驗證 GMGN。兩者對同一錢包的比對結果見決策紀錄。
- **評分只看領頭錢包在 t 之前的交易**：勝率、已實現報酬、持有時間、進場時代幣年齡等，以 GMGN 的池子側金額計算（與費用無關的交易品質）；跟單者的成本在模擬時另外扣。
- **儲存與執行**：沿用現有的 TypeScript 程式（Parquet + DuckDB、`npm run sw`）。回測是 CLI 指令，輸出報告檔，不做網頁。

## 回測設計

- **錢包池**：評估期內每週一次，以 Dune 漏斗在該週一 00:00 的時間上界重播，取當時的候選錢包（參數同現行漏斗：回看 14 天、最高市值 2,000 SOL、k = 3、每天 50 筆上限、N = 50）。
- **評分**：每個候選錢包在該週一之前的交易 → 各項指標 → 排名。第一版不做加權總分，每個指標單獨排名、單獨檢定。
- **跟單模擬**：該週內，前 N 名錢包的每筆買入，跟單者在 t + L 秒以當時價格買入同額 SOL（或固定額度），在領頭錢包賣出時跟著賣（第二種變體：固定持有時間）。扣除手續費 f 與單邊滑價 s。
- **基準**：同一週候選錢包的隨機 N 名；以及「每一筆 pump.fun 畢業代幣都買」。
- **輸出**：每個指標、每種參數組合的平均報酬、中位數、勝率、報酬分布與 bootstrap 信賴區間；延遲 L ∈ {2, 5, 15, 60} 秒、滑價 s ∈ {1%, 3%, 5%} 的敏感度。
- **成功判準**：至少 8 週、至少一個指標的前 N 名，在 L = 5 秒、s = 3% 下，每筆報酬的 95% 信賴區間下界 > 0，且顯著優於隨機基準。
- **多重檢定**：指標數 × 參數組合數很多，採留出期（最後 2 週不參與挑選），挑出的組合只在留出期驗證一次。

## 里程碑

| 階段 | 交付 | 驗收 |
| --- | --- | --- |
| R0 資料可信（大部分已完成） | Helius 管線、對帳、快照；穩定幣換算；GMGN 抽樣比對 | 50 個漏斗錢包對帳可信列 ≥ 95%；穩定幣交易換算完成；GMGN 與 Helius 的交易覆蓋與方向一致率 ≥ 99%、token 數量一致率 ≥ 95%（差異需可解釋） |
| R1 漏斗重播 | 以時間上界執行的每週漏斗、結果存檔 | 同一週重跑結果相同；重播結果不含任何該週之後才出現的錢包 |
| R2 回測 | 評分、跟單模擬、基準、報告 | 報告能回答開頭的問題；point-in-time 性質測試通過（加入 t 之後的資料，t 的結果不變） |
| R3 決策 | 依 R2 結果決定是否做即時訊號 | — |

## 成本與限制

- **GMGN**：免費方案的漏桶速率 5/5，每個錢包請求權重 3，約每秒 1.7 次；需申請個人 API key（Ed25519 金鑰對），公開測試 key 只供測試。
- **Helius**：免費方案 enhanced API 每秒 2 次；回補高頻錢包耗時長，首次回補上限 500 頁。
- **Dune**：漏斗一次查詢約 15 分鐘（回看 14 天加 curve 多讀 30 天）；8 週的重播約 8 次查詢，credits 用量需在 R1 開始時量測。
- **Vybe**：免費方案每分鐘 4 次、每月 12,000 credits，不適合批量；有關聯錢包與 PnL，保留為備案。

## 開放問題

- [ ] 跟單者的成交價來源：GMGN 1 分鐘 K 線（粒度粗）或 Dune 在 [t+L, t+L+10s] 的實際成交（精確但貴）
- [ ] 同一筆交易內賣出多個代幣（我們歸為 complex、GMGN 拆成個別賣出）在 Helius 管線如何分配 SOL
- [ ] 漏斗回看天數與門檻是否隨回測結果調整（調整本身要納入多重檢定）
- [ ] GMGN 標籤與首筆入金來源的每日存檔從何時開始
