Scope: startup config validation, strict parsing, no implicit DB fallback; local permission catalog and role mapping; explicit service permissions; creation-only admin bootstrap; regression tests and migration documentation. Continue in codex/audit-fixes worktree. Preserve Privy DID identity, user ownership checks, existing HTTP shapes and single-replica deployment.

Design: startup validation produces typed app/database/auth/telegram/hyperliquid settings without connecting to dependencies. Runtime helper reads remain for compatibility in this batch; a whole-service DI config migration is deferred. AuthGuard authenticates and retains legacy human @Roles checks. PermissionGuard enforces explicit permissions after AuthGuard. User/admin roles remain; no dynamic role tables. Service callers receive only AUTH_SERVICE_PERMISSIONS; missing means none. /me permissions are deferred to avoid requiring frontend fixture/contract migration in this batch. Admin email bootstrap applies only at account creation. Profile retry may populate email but cannot promote an existing account.
