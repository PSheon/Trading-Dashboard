### 共用的對帳方法（跟單執行、投資組合都用這一套）

每一筆跟單調整都拿五個來源互相比對，**以 Hyperliquid 為準**：

| # | 來源 | 讀什麼 |
| --- | --- | --- |
| L | 主網 `userFillsByTime`（交易員） | `tid`、`coin`、`side`、`sz`、`px`、`startPosition`、`time` |
| D | Orbie `copy_live_dispatches` | `leader_time`、`received_at`、`sent_at`、`status`、`reason`、合併的來源 tid |
| O | 測試網 `orderStatus`（以 Orbie cloid 查）＋ `userFills`（跟單帳戶） | `oid`、`sz`、`px`、`fee`（已含 `builderFee`）、`closedPnl` |
| C | 測試網 `clearinghouseState`（跟單帳戶） | `assetPositions[].position.szi／entryPx／unrealizedPnl／leverage`、`marginSummary.accountValue`、`withdrawable` |
| P | Orbie `GET /me/copy/live/portfolio`、`/me/copy/execution-wallets/:id/snapshot`、`/statement`、`/activity` | 持倉、權益、損益、手續費、ROI |

公式（Orbie 的模型，見 `docs/copydog-copy-trading-mechanics-2026-10-02.md` §5；CopyDog 的確切公式未公開）：

- 目標名目 = 交易員本次名目變化 × 跟單策略權益 ÷ 交易員有效權益（ratio）；fixed 模式為固定名目。
- 下單數量 = 向下捨入到該幣 `szDecimals`（`copy/copy-math.ts:136 floorSize`）。減倉以比例計，零頭留在 carry（`copy-math.ts:126 reduceWithCarry`）。
- 限價 = 中價 ±`maxSlippageBps`，再依 HL 價格規則（5 位有效數字、小數位 ≤ 6 − szDecimals）取保守方向（`copy/live/copy-live-source-planner.ts:110 conservativeLimit`）；IOC。
- 最小名目 = `limits.minOrderNotionalUsd`（HL 交易所下限 $10）；低於者 `below_min_notional`，開倉累積到達標再送，最多 15 分鐘（`live-worker/copy-live-adjustments.ts`，`94a8af3b`）。
- 手續費：O 的 `fee` 已含 builder；testnet builder = 0（Paul 決定 7）。Orbie 記帳的手續費必須**逐筆等於** O 的 `fee`，不可再加 builder。
- 權益：P 的權益 = C 的 `accountValue`（同一讀取時間，誤差 ≤ $0.01）。持倉：P 的 `szi` = C 的 `szi`（完全相等）。
- 損益：P 的總損益 = C 的 `accountValue` −（入金 − 返還），P 的已實現 = Σ O.`closedPnl` − Σ O.`fee` ± funding；ROI = 總損益 ÷ 淨入金。
