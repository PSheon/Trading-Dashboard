# 競品分析 — CopyDog 類產品的結構性弱點與改進方向

Sep 29, 2026

## 1. 前提與資料來源

**CopyDog 沒有可查到的公開產品文件。** 三次搜尋只找到同類產品（Dexly、HyperX、ApexLiquid、Hyperdash、BitMEX 的 Hyperliquid 跟單）。因此本文分兩層：

1. **結構性弱點**：從跟單/大戶追蹤這類產品的本質推導，適用於整個類別，同類產品的公開描述可佐證。這一層是可靠的。
2. **CopyDog 專屬弱點**：列成第 4 節的待驗證清單，需要 CopyDog 的網址、截圖或匯出檔才能填實。未驗證前不寫進 PRD。

本文的用途不是貶低 CopyDog，而是回答一個問題：**既然 CopyDog 已經存在，我們自建的價值在哪裡？** 答案必須具體到能對應 PRD 的某條需求。

## 2. 這類產品的價值鏈

所有跟單/大戶追蹤平台都是同一條鏈：**發現 → 評估 → 訊號 → 執行 → 回饋**。商業平台的收入來自「執行」（builder fee、分潤、訂閱），所以資源會往執行集中，前面的「評估」與最後的「回饋」是它們結構上最弱的兩段。

| 環節 | 平台做什麼 | 平台的收入從哪來 | 結構上的傾向 |
| --- | --- | --- | --- |
| 發現 | 排行榜、地址列表 | 無直接收入 | 用最吸睛的指標（短期 ROI）排序 |
| 評估 | 顯示績效指標 | 無直接收入 | 指標淺，缺回撤、樣本數、一致性 |
| 訊號 | 通知或直接觸發跟單 | 無直接收入 | 以單筆成交為單位，噪音高 |
| 執行 | 代使用者下單 | **主要收入** | 鼓勵多跟、多交易 |
| 回饋 | 跟單績效頁 | 無直接收入 | 幾乎沒有「訊號品質」的回饋 |

我們的系統只做前三段加回饋，不做執行。這不是功能少，而是把資源放在商業平台沒有動機做好的地方。

## 3. 結構性弱點與我們的改進

每一項：弱點是什麼、為什麼是結構性的（不是做不好，是沒動機做）、我們怎麼做、對應 PRD 哪條。

### 3.1 排行榜的倖存者偏差

**弱點**：以 7/30 天 ROI 或 PnL 排序，選出的是這段期間運氣好且槓桿高的地址，不是可持續的交易者。榜單每週大換血，但平台不會告訴你換血率。

**為什麼結構性**：排行榜的目的是吸引人跟單，短期高 ROI 最吸睛。加上回撤與樣本數會讓榜首看起來不那麼誘人。

**改進**：把 CopyDog 名單當作候選池而非結論。名單版本化，**排名變動率本身是訊號**；用自存資料算 30 天已實現 PnL、最大回撤、交易筆數、平均持倉時間，用自己的指標重新排序。→ PRD A1、A4、D2

### 3.2 沒有回撤與樣本數

**弱點**：一個地址 3 筆交易 300% ROI 和 300 筆交易 40% ROI 在榜上長得一樣。

**改進**：Leaders 頁強制顯示交易筆數與最大回撤；筆數 < 20 的地址標灰。勝率以完整倉位計算，用 Hyperliquid 給的 closed\_pnl 加總。→ PRD D2、決策紀錄「勝率與 PnL 單位」

### 3.3 訊號粒度是單筆成交

**弱點**：通知以 fill 或單一訂單為單位。大戶分批建倉時你會收到十則小通知，真正的「他在建一個大倉位」這件事反而看不到。

**為什麼結構性**：平台的訊號是給執行引擎用的，執行需要逐筆；給人看的聚合是額外成本。

**改進**：三層粒度：fill（存）→ action（1 秒聚合，分類開/加/減/平/翻）→ episode（15 分鐘累計）。通知只看 action 與 episode。→ PRD W3、決策紀錄「聚合第二層」

### 3.4 沒有群體視角

**弱點**：所有平台的介面都是「一個地址的頁面」。100 個大戶同時看多某幣這件事，沒有任何一頁能看到。

**為什麼結構性**：跟單的商業模型是「你跟某一個人」，群體視角不產生跟單行為，也就不產生收入。

**改進**：這是我們最大的差異。幣種 × 多空名目 Heatmap、持倉地址數變化、共識規則（N 個地址 T 分鐘內同向開倉）、淨偏向翻轉、集體離場。→ PRD R6–R8、D4

### 3.5 歷史不自有

**弱點**：平台直接讀 Hyperliquid API，而 Hyperliquid 只保留有限成交歷史、不提供權益曲線。所以平台的績效圖要嘛短，要嘛是它自己存的但不給你。

**改進**：fills 與 equity\_snapshots 從第一天起落庫，永不刪除；存 raw jsonb 以便重算。三個月後我們的資料比任何只讀 API 的平台完整。→ PRD 設計原則 1、資料模型

### 3.6 通知不可評分

**弱點**：平台不記錄「通知後價格怎麼走」，所以你永遠不知道哪類通知有價值，只能靠感覺。

**為什麼結構性**：評分會暴露多數通知沒用，對平台是負面資訊。

**改進**：每則通知寫日誌，1h / 4h / 24h 後回填中間價；Alerts 頁按規則統計平均變化，每週淘汰噪音規則。→ PRD N2、N3、D5、M4

### 3.7 激勵錯位

**弱點**：收入來自 builder fee 或分潤，平台的利益是你多跟、多交易。榜單可能有付費上榜或推廣位。

**改進**：自用、唯讀、不執行，系統沒有任何理由要你多交易。→ PRD 非目標

### 3.8 金鑰託管風險

**弱點**：非託管跟單仍需平台持有 agent key；agent 不能提款，但能把你的倉位開到爆。

**改進**：第 1 版不持有任何私鑰。→ PRD 非功能需求「安全」

### 3.9 名單黑盒

**弱點**：不知道地址為什麼入榜、是不是 vault、是不是某大戶的子帳號之一。Vault 的「權益」是 TVL，和個人地址的意義完全不同。

**改進**：匯入時判斷並標記 vault；每個地址保留「哪一版名單、什麼排名進來的」；停用理由可記錄。→ PRD A3、決策紀錄「Vault 地址」

### 3.10 資料鎖定

**弱點**：無匯出、無 API。你在平台上累積的觀察無法帶走，也無法拿去回測。

**改進**：資料在自己的 Postgres，schema 帶 chain 欄位，之後 Solana 聰明錢包目錄共用同一套。→ PRD 設計原則 5

## 5. 差異化定位總結

一句話：**CopyDog 幫你選一個人來跟；我們幫你看 100 個人在做什麼，並記住他們做過什麼。**

三個真正的差異，依重要性排序：

1. **群體視角**（3.4）：這是商業平台結構上不會做的，也是 100 個地址才有意義的功能。
2. **自有歷史 + 可評分**（3.5、3.6）：時間越久價值越大，且是之後回測與跟單的基礎。
3. **無激勵錯位**（3.7、3.8）：系統不會推你交易，也不碰你的資產。

其餘弱點（3.1、3.2、3.3、3.9、3.10）是「做得比較好」而非「它做不到」，是必要條件不是差異化。

**對 PRD 的影響**

- 第 3 節的每一條改進都已對應到 PRD 的需求編號；若第 4 節驗證後發現 CopyDog 已做到某項，該項需求降一級優先。
- 第 4 條（跨地址視圖）是唯一會動搖定位的驗證項，應最先確認。
- 本文驗證完成後，PRD 第 1 節「要解決的問題」應改寫為引用本文第 5 節。
